# Deploying Family Hub (Neon + Render)

One-time setup takes about 15 minutes. After that, every push to `main` redeploys automatically.

## Who does what

| | Who | What it means for you |
|---|---|---|
| Database server (Postgres) | **Neon** (hosted) | Neon runs, patches, and backs up the server. Nothing to install. |
| Database tables | **The app** (Flyway) | On every start the app applies any new `db/migration/V*.sql` files. Never create or change tables by hand. |
| Neon & Render accounts, secrets | **You** | Create the two accounts once and paste the connection string + passwords into Render. Secrets never go in git. |
| Schema changes | **Code** | A new feature that needs a table change comes with a new migration file (`V8__...sql`); never edit an old one. |

## 1. Neon (database)

1. Sign up at https://neon.tech (free plan is plenty for a household).
2. **Create project**: name `family-hub`, Postgres version 17, region **AWS Europe Central (Frankfurt)** (closest to Cyprus and to Render's Frankfurt region).
3. Database name: `familyhub` (or keep `neondb`).
4. On the project dashboard click **Connect** and copy the connection string. Use the **direct** one, not "Pooled connection",
   because Flyway migrations want a direct connection and the app keeps its own small pool. It looks like:
   `postgresql://familyhub_owner:npg_xxxx@ep-cool-name-123456.eu-central-1.aws.neon.tech/familyhub?sslmode=require`
   You can paste it as is: the app converts it to JDBC itself.

## 2. Render (app hosting)

1. Sign up at https://render.com with your GitHub account and allow it to see the `family-hub` repo.
2. **New → Blueprint** → pick the repo. Render reads `render.yaml` and asks for the secret values:
   - `DATABASE_URL`: the Neon string from step 1.4
   - `APP_ADMIN_USERNAME` / `APP_ADMIN_PASSWORD`: your first login (only used while there are no members yet)
   - `REMEMBER_ME_KEY` is generated by Render automatically.
3. **Apply**. The first build takes ~5-8 minutes (Node + Maven inside Docker). Watch the logs for
   `Successfully applied 7 migrations` and `Started FamilyHubApplication`.
4. Open `https://family-hub-xxxx.onrender.com`, log in, and add the other members from **Members**.

If something is missing, the log starts with `Production configuration is incomplete:` followed by the list.

## 3. After the first login

- Remove `APP_ADMIN_PASSWORD` from Render (Environment tab). It is only read when the member table is empty.
- Check the timezone: the Goals page highlights today's column and the Chores "Today" tab uses the Cyprus date.

## Good to know

- **Free plans sleep.** Render's free web service stops after ~15 minutes without visits; the next visit takes
  about a minute to wake up. Neon's free database also suspends when idle (wakes in under a second).
  The paid Render "Starter" plan (~$7/month) stays awake.
- **Staying logged in.** Tick "Remember me": restarts (deploys, sleep) end sessions, but the remember-me cookie
  (30 days) logs you back in. Changing `REMEMBER_ME_KEY` logs everyone out.
- **Backups.** Neon keeps a restore window (point-in-time restore, a few hours to days depending on plan) and lets you
  create a branch from any moment in that window. For a long-term copy, export now and then:
  `pg_dump "<neon connection string>" -Fc -f familyhub-YYYY-MM-DD.dump`.
- **Run the prod build locally** (needs Docker): copy `.env.example` to `.env`, fill it in, then
  `docker build -t family-hub .` and `docker run -p 8080:8080 --env-file .env family-hub`.
- **Postgres migration test.** `PostgresMigrationTest` runs every migration on a real Postgres 17 container.
  It is skipped when Docker isn't running, so install Docker Desktop to have it run with `.\mvnw.cmd test`.
